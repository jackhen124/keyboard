# keyboard

My keyboard layouts. The active work is the **ZSA Voyager** (QMK), migrated from
the **Glove80** "Glorious Engrammer" (QWERTY base). The Glove80 layout is kept
here only as the reference the Voyager keymap was ported from.

## Repo layout

```
keyboard/
├── voyager/                     # active: ZSA Voyager (QMK)
│   ├── flash/                   # the ONLY files compiled into firmware
│   │   ├── keymap.c             # the keymap: 5 layers (Base, Sym, Num, Nav, Mouse)
│   │   ├── lighting.c/.h        # RGB lighting module (pattern + color, chosen independently)
│   │   ├── config.h             # home-row-mod tuning (TAPPING_TERM, CHORDAL_HOLD, …)
│   │   └── rules.mk             # QMK feature toggles (MOUSEKEY_ENABLE, SRC += lighting.c)
│   ├── gen-keymap-images.py     # parses flash/keymap.c → images/*.svg (see below)
│   └── voyager.keymap.json      # generated by the script; input to keymap-drawer
├── glove80/                     # reference: original Glove80 (ZMK / Oryx) layout
│   ├── glove80-zmk-layout.keymap
│   └── glove80-zmk-layout.json
├── images/                      # generated per-layer keymap SVGs
├── oryx-tricky-features.md      # Glove80/Oryx features not (yet) ported
├── voyager-base-layer.md        # notes on the Voyager base layer
├── Get-LatestFirmware.ps1       # download the latest CI firmware artifact
└── .github/workflows/
    ├── build-voyager.yml        # CI: compile firmware on keymap changes
    └── draw-keymap.yml          # CI: redraw images/ + commit them back
```

## Building & flashing the Voyager

The firmware is built in CI. The workflow at
**`.github/workflows/build-voyager.yml`** (GitHub requires workflows to sit
under `.github/workflows/`) copies everything in **`voyager/flash/`** into
a QMK checkout and compiles it.

1. **Push** any change under `voyager/flash/` to GitHub (or trigger the
   *Build Voyager firmware* workflow manually from the Actions tab).
2. Open the **Actions** tab → the latest *Build Voyager firmware* run.
3. Download the **`voyager-jack-firmware`** artifact. GitHub always hands you a
   **`.zip`** (that's just how it packages artifacts), so **unzip it** — inside
   is the actual `zsa_voyager_jack.bin` firmware file. That `.bin` is the thing
   you flash; the `.zip` itself can't be flashed. (Or run
   `./Get-LatestFirmware.ps1` to fetch + unzip it for you.)
4. Put the Voyager into **bootloader mode**: press the small reset button on the
   board, **or** hold the `_MOUSE` layer (right-inner thumb) and tap `QK_BOOT`
   (top-left key) once this keymap is already running.
5. Flash the `.bin` with any **one** flashing tool — you only need one, and the
   `.bin` never flashes itself:
   - **Wally** (GUI, https://www.zsa.io/wally): select the unzipped `.bin` and
     click flash.
   - **Keymapp** (GUI, https://www.zsa.io/keymapp): ZSA's newer app, same idea.
   - **zapp** (CLI, https://github.com/zsa/zapp): `zapp flash zsa_voyager_jack.bin`.
     Optional — only if you prefer the terminal. Note its `zapp flash <url>`
     shortcut works with **Oryx** URLs, not GitHub artifact links, so you still
     download + unzip first.

## Editing the keymap

Edit `voyager/flash/keymap.c` directly. The `LAYOUT_voyager()` macro takes
exactly 52 keys per layer in this order:

```
row0 L(6)  row0 R(6)
row1 L(6)  row1 R(6)
row2 L(6)  row2 R(6)
row3 L(6)  row3 R(6)
thumbs: L-outer  L-inner  R-inner  R-outer
```

Keep each layer at 52 arguments or the build fails. Commit + push and the
workflow rebuilds automatically.

> Note: this is an approximation of the Glorious Engrammer, not a 1:1 clone.
> The home-row mods ARE close to Sunaku's — bilateral holds (`CHORDAL_HOLD`),
> prior-idle gating (`FLOW_TAP_TERM`), and per-finger tapping terms. Still
> missing: the magic/repeat key and emoji/World layers. See
> [`oryx-tricky-features.md`](oryx-tricky-features.md) for those gaps.

## Keymap images

`voyager/gen-keymap-images.py` parses `voyager/flash/keymap.c` directly (no QMK
toolchain) and renders one SVG per layer into `images/`.

**This runs automatically in CI.** The
**`.github/workflows/draw-keymap.yml`** workflow redraws the images on every
push that touches `voyager/flash/keymap.c` (or the script) and commits the
refreshed SVGs back to the repo, so `images/` is always up to date. The
auto-commit is tagged `[skip ci]` and only changes `images/`, so it never
retriggers a firmware build.

To preview locally before pushing:

```
pip install keymap-drawer          # once
python voyager/gen-keymap-images.py
```
